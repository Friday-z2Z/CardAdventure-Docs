# 分享与裂变

> 补全 00_Compliance / 01_Monetization 的社交拉新设计。原则：**只做主动分享，不做强制分享**。

## 1. 分享点位（V1 三处）

| 点位 | 触发 | 分享内容 | 激励 |
|---|---|---|---|
| 通关晒图 | 结算面板"分享战绩" | 卡面：关卡数 + 首领击杀 + 稀有掉落图 | 无（荣誉驱动） |
| 图鉴炫耀 | 图鉴页"分享收集进度" | 已收集数 / 全集进度条 | 无 |
| 排行榜挑战 | 好友榜页"发起挑战" | "我在第 N 关，来超越我" | 无 |

- 失败复活**只用激励视频**（01_Monetization.md），不设"分享复活"——避免把社交压力绑定在负反馈上。

## 2. 被动侧（被分享者）

- 点开分享卡直接进小游戏并落到**该关卡入口**（分享携带 levelId 参数），新玩家看到"他的进度"与"从这一关开始玩"引导。
- 落地即引导完成第 1 关（15_Tutorial.md），不强制跳关。

## 3. 激励边界（微信审核红线）

1. 不做"分享后才能继续游戏/领奖"的强制路径。
2. 不做"分享到不同群奖励翻倍"的诱导刷量。
3. 允许：分享后获得小额金币（每日 ≤1 次，Balance 表），文案不得出现"必须""否则"。
4. 分享回调 wx.onShareAppMessage 不依赖 success 回调发奖（微信已不保证回调），改为点击分享动作即发（每日一次上限控制）。

## 4. 素材规范

- 分享图 5:4，主视觉用当前关卡主题背景 + 卡牌（03_UI 资产复用），不新增美术规格。
- title ≤ 20 字，模板登记 CopyDeck（`copy_share_*`）。

## 5. 接口与埋点

- 统一走 IShareService（00_Architecture.md 第 5 节）：`share(scene, payload)`；scene 枚举登记本文第 1 节。
- 埋点 `share_sent` / `share_opened`（06_Analytics.md），按 scene 统计分享→打开→留存转化。
