# 开发路线图与里程碑

> 来源：总规格书第十一、十七章。

## 1. 总体顺序

**规则确定 → 技术验证 → 核心原型 → 系统架构 → MVP → 关卡扩展 → UI 打磨 → 性能优化 → 测试验收 → 发布交付。**

不先做大量美术、不先做 500 关——核心规则变化时，提前制作的内容可能重做。

## 3. 第一阶段范围（MVP）

主菜单、关卡选择、单局卡牌探索、卡牌堆（5×5 矩阵盘，MVP 2～3 堆少堆盘）、基础敌人、资源卡、恢复卡、陷阱、出口、5～10 种基础道具、生命/食物/金币、基础状态效果、失败与通关、存档、10～20 个测试关卡、自动化规则测试。

先保证玩家能完整玩一局，再加复杂机制。

## 6. 结论：十条执行原则

1. 卡牌统一数据结构；2. 道具统一使用流程；3. 战斗/资源/状态/奖励走统一规则引擎；4. UI 只展示与输入；5. 关卡统一格式且可自动验证；6. 500 关 = 固定设计 + 规则组合 + 难度控制；7. 代码模块化、类型化、配置驱动；8. 重要功能必须有测试；9. 开发任务必须有验收条件；10. 交付含工程、资源、配置、文档、测试报告。

**先完成一套能稳定运行、可测试、可扩展的核心游戏，再规模化到 500 关。**
