# 游戏总览

> 来源：《卡牌奇旅》总规格书 V1.0 第一章。本文是策划与程序共享的项目定位文档。

## 1. 项目定位

《卡牌奇旅》是一款以卡牌选择、资源管理、探索冒险和策略决策为核心的轻度 Roguelike 卡牌游戏，微信小游戏平台，竖屏优先，目标 500 关。

玩家在每个关卡中通过处理左右两组卡牌，不断解决敌人、获取资源、使用道具、恢复状态并寻找出口。

核心乐趣是持续面对以下决策：

- 当前应该处理哪张卡牌？
- 先击败敌人，还是先获取资源？
- 当前生命值是否足够继续探索？
- 是否应该消耗道具来降低风险？
- 是否应该保留强力道具应对后续敌人？
- 当前关卡是否值得继续探索，还是应该优先寻找出口？

## 2. 三个设计目标

| 目标 | 说明 |
|---|---|
| 易上手 | 无需复杂教程即可理解基本操作 |
| 有策略 | 每次行动都会影响生命、资源、道具或后续选择 |
| 可持续扩展 | 500 关通过配置、规则组合和主题变化实现，而非重复摆放卡牌 |

## 3. 核心体验四关键词

| 关键词 | 对应设计 |
|---|---|
| 选择 | 玩家从左右卡牌堆中决定下一步行动 |
| 风险 | 敌人、陷阱、资源消耗和状态变化 |
| 收获 | 金币、食物、装备、道具及关卡奖励 |
| 成长 | 新机制、难度递进、永久解锁和关卡推进 |

## 4. 交付目标

### 第一阶段：可发布的核心版本

- 主界面及关卡入口
- 完整的核心卡牌玩法
- 玩家状态与资源系统
- 战斗和效果结算系统
- 道具系统
- 关卡生成与通关判断
- 存档和关卡进度
- 10～20 个经过测试的正式关卡
- 基础音效、动画、引导和失败重试
- 微信小游戏基础适配及发布测试

### 第二阶段：500 关内容版本

- 500 个关卡配置
- 多阶段难度曲线
- 多种敌人、事件、陷阱和奖励组合
- 完整的关卡验证工具
- 关卡数据检查与批量测试
- 性能优化、内容平衡及正式交付

## 5. 重要原则

**500 关不是开发初期一次性制作的 500 张地图，而是通过统一关卡格式、卡牌配置、主题规则和验证工具逐步生产的内容系统。**

开发顺序必须是：规则确定 → 技术验证 → 核心原型 → 系统架构 → MVP → 关卡扩展 → UI 打磨 → 性能优化 → 测试验收 → 发布交付。

技术路线：**方案 B（Cocos Creator + TypeScript）已选定**。理由：场景编辑、动画与资源工作流成熟，个人开发用编辑器提效明显；构建面板直出微信小游戏包。引擎隔离约束见 02_Development/00_Architecture.md 第 6 节（核心逻辑禁 import 引擎，保证可测试与可迁移）。
