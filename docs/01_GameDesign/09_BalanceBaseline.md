# 数值基线表（平衡方案冻结版）

> 新增章节。冻结平衡方案一并给出 MVP 数值基线，作为 Balance 表（06_DataBalance.md 第 3 节）的起点。所有数值为原型基线，须经实测与模拟调整（测试方案见 11_Testing.md）。

## 1. 已冻结的平衡决策

**方案一：玩家初始属性不动，敌人数值从低起步。**

| 对比项 | 方案一（✅采纳） | 方案二（❌弃） |
|---|---|---|
| 玩家初始 Attack | 1（不变） | 提至 3 |
| 早期敌人 | HP 2～5、ATK 1～2 | 维持 HP8/ATK3 |
| 食物消耗节奏 | 不受影响 | 数值通胀需重调全表 |
| 装备成长空间 | 武器 +1 攻击体感明显 | 早期装备被稀释 |
| 早期战斗体感 | 2～5 回合短战斗，压力来自选择而非数值 | 7～8 回合拉锯，前期即劝退 |

冻结理由：卡牌游戏的压力应来自「选哪边、用什么、保不保留」的决策，而非数值差；低数值起步给 500 关的成长曲线留足空间。

## 4. 敌人基线（按阶段）

| 阶段（关卡） | HP | ATK | DEF | 单场预期回合 | 备注 |
|---|---|---|---|---|---|
| 一（1～20） | 2～5 | 1～2 | 0～1 | 2～5 | 见 07_CardCatalog.md 首批 5 敌 |
| 二（21～80） | 4～8 | 2～3 | 0～1 | 3～5 | 引入状态型敌人（毒/灼烧） |
| 三（81～180） | 6～12 | 2～4 | 1～2 | 3～6 | 精英：数值 ×1.5～2 + 一个特殊机制 |
| 四（181～320） | 8～16 | 3～5 | 1～2 | 4～7 | 强调组合与资源压力 |
| 五（321～500） | 10～24 | 3～6 | 1～3 | 4～8 | 首领多阶段，数值封顶靠机制 |

约束：敌人数值增幅必须慢于玩家装备/道具成长；任何阶段不允许「数值差导致必败」；DEF ≤ 3（保证 max(1, ATK+加成-DEF) 公式下玩家始终有 1 点保底伤害）。

## 5. 奖励基线

| 来源 | 基线 |
|---|---|
| 普通敌人 | 金币 1～4，部分 +1 食物 |
| 精英敌人 | 金币 6～10 或道具 ×1 |
| 资源卡 | 金币 3～8 / 食物 2～3 |
| 通关奖励 | 金币 5～10 + 按关卡表（rewardConfig） |
| 商店价格 | 普通道具 5～8 金币，稀有 12～20（收**钱包金币**，16_Shop.md） |

补充约束（金币双层制，11_Resources.md §3）：关卡净收入预算带（第 4 节 ±30%）仍按**局内金币**核查；钱包金币的全局平衡以"局内收入 → 转存 → 商店消耗"闭环监控，商店是钱包的主消耗口，防通胀校验纳入 LevelValidator"赛前采购"两端模拟。

约束：Gold 不足以支付时不允许负数交易；道具获取路径受 LevelValidator 检查（06_DataBalance.md）。

## 7. 维护流程

1. 调整只改 Balance 表 → 导出 → Validator → 模拟回归（06_DataBalance.md 第 3 节）。
2. 每次变更记录原因与影响范围。
3. 观测指标（通关率、剩余资源、道具频率）见 06_Levels.md 第 6 节；出现单一最优策略即触发复审。**复审触发器**：level_fail.cause 分布异常、boss_phase 卡点、DIFF 预测与实际通关率偏差 >15%（06_Levels.md §3.1.2）、钱包存量增速越阈（16_Shop.md §5）。
