# 核心循环与单局流程

> 来源：总规格书 2.1、2.2、2.4。本文定义单局的完整流程、布局与食物消耗规则。

## 1. 单局流程

1. 玩家进入关卡。
2. 系统读取关卡配置。
3. 初始化玩家本关状态。
4. 生成或加载本关卡牌布局。
5. 展示左右两个可操作卡牌堆。
6. 玩家选择其中一侧的顶层卡牌。
7. 系统检查操作是否合法。
8. 执行卡牌效果。
9. 统一结算伤害、资源、状态和触发效果。
10. 检查玩家是否死亡、是否满足胜利条件。
11. 若关卡仍在进行，则更新可操作卡牌。
12. 玩家继续决策。
13. 玩家满足出口条件并成功离开后，关卡通关。
14. 结算奖励、保存进度并进入下一关。

流程必须保证：

**玩家操作 → 规则验证 → 效果结算 → 状态更新 → 胜负判断 → UI 刷新。**

UI 不负责判断游戏规则，所有操作最终必须交由游戏逻辑层处理。

状态机视角的正式定义见 `../02_Development/02_StateMachine.md`；效果串行结算见 `../02_Development/03_ActionQueue.md`。

## 2. 关卡布局（竖屏）

| 区域 | 高度占比 | 内容 |
|---|---|---|
| 顶部状态栏 | 10% | HP / Food / Gold / 护盾 |
| 关卡信息与目标 | 8% | 关卡名、目标提示 |
| 中央卡牌展示 | 42% | 效果演出、飘字、事件面板 |
| 左右卡牌堆 | 27% | 双侧可操作卡牌 |
| 底部道具栏 | 13% | 道具按钮 + 安全区间距 |

比例只是初始参考，须按屏幕比例、安全区与操作舒适度调整。

## 3. 卡牌堆规则

- 左右两侧各维护一组卡牌：顶层可操作卡牌、被遮挡的后续卡牌、剩余数量、堆状态。
- 默认只允许操作顶层卡牌；处理顶层后进入结算，下一张成为顶层。
- **左右卡牌堆是决策入口，不是两个独立系统**：两侧共享同一套规则、结算、状态管理和存档。

## 4. 食物消耗机制

### 规则

1. 成功完成一次有效卡牌操作后，按规则扣除食物。
2. 特殊卡牌可豁免食物消耗（通过配置 `actionCost`）。
3. 食物不足时不能无成本继续探索。
4. 食物不足的处理规则必须统一，不允许各卡牌自行决定。
5. 失败、胜利及特殊事件中的食物结算必须有明确规则。

### 原型数值

- 普通有效操作：消耗 1 点食物。
- 特定事件、技能或道具：免除本次消耗。
- 食物不足：每次有效操作额外损失 2 点生命。
- 扣除后 HP ≤ 0 立即进入失败流程。

### 结算顺序（必须遵守）

**验证操作 → 确认卡牌效果 → 扣除行动食物成本 → 结算卡牌效果 → 结算持续状态 → 检查死亡和胜利。**

特殊卡牌可以通过配置调整食物成本，但不能绕过统一结算器。

## 5. 死亡与重试模型

- 玩家 HP 归零即本关失败，无自动复活。
- 失败后重试从关卡初始状态重建（含关卡种子），不保留本关中途获得的资源与道具。
- 关卡进度（已解锁关卡、永久成长）不因失败丢失。
- 失败时 UI 必须展示死因（伤害来源 / 食物耗尽 / 状态效果），供玩家理解失败原因。
- 死亡后可看激励视频复活（以 50% 生命原地复活、每关一次、Combo 清零），也可直接放弃——广告永远是可选项。完整频控与点位见 `../04_Platform/01_Monetization.md` 第 2 节。
