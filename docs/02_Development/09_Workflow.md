# 开发工作流与 AI 协作规范

> 来源：总规格书第十章。本文是开发流程、Git 与 AI 协作的执行依据。

## 1. 每个开发任务的标准流程

1. 明确需求。2. 明确输入与输出。3. 确认影响的模块。4. 编写或更新类型。5. 实现核心逻辑。6. 编写测试。7. 检查异常情况。8. 验证 UI 或数据表现。9. 运行回归测试。10. 更新文档。11. 提交代码。12. 记录变更。

禁止在没有明确需求的情况下直接大范围修改代码。

## 2. Git 规范

分支：`main`（稳定）/ `develop`（集成）/ `feature/xxx` / `fix/xxx` / `release/xxx`。

提交信息示例：

```text
feat: add item usage system
fix: prevent duplicate enemy damage
refactor: separate card effect resolver
test: add level validation cases
docs: update level generation rules
```

每次提交围绕单一目标。

## 3. 代码审查清单

合并前至少检查：符合现有架构；未重复实现已有逻辑；未引入未经验证的常量；不会导致状态不一致；无异步重复操作；有相应测试；文档已更新；不影响存档兼容；不增加资源/包体负担（对照性能预算 05_Performance.md）；事件已登记（04_EventCatalog.md）。

## 4. AI 编程协作规范

AI 可以做：生成类型定义、实现独立业务模块、编写单元测试、创建关卡配置、检查代码重复、分析错误日志、生成文档、优化重复性内容生产。

AI 未经确认不得：更换技术栈、重构整个项目、删除已有系统、修改核心游戏规则、擅自更改存档结构、创建未经审核的大量关卡、修改 UI 设计令牌、引入未知依赖。

```text
边界条件：
验收标准：
需要新增的测试：
影响系统：
风险：
回滚方案：
```

（后三项为采纳评审建议十四新增，AI 每次任务必须输出。）

CodeBuddy 等助手的**项目上下文入口**：仓库根的 `AGENTS.md`（先读文档索引、关键约束、常用命令）。修改 AI 约束时须同步更新该文件。

AI 完成后必须人工检查并运行测试。**不能因为代码能够编译，就认为功能已经正确。**
