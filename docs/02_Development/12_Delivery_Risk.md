# 交付标准与项目风险

> 来源：总规格书第十五、十六章。

## 1. 交付物清单

### A. 工程文件
完整源码、项目配置、依赖配置、资源目录、构建脚本、测试脚本、关卡数据、卡牌数据、道具数据、数值配置。

### B. 设计文档
本 docs 目录全部内容 + 发布说明 + 版本变更记录。

### C. 测试材料
单元/集成测试结果、500 关数据检查报告、固定关卡通关验证记录、设备适配记录、已知问题清单、RC 验收记录。

### D. 美术资源
卡牌框架、卡牌图标、敌人图形、道具图标、背景、UI 组件、动画、音效、字体授权信息、**第三方素材授权清单**（itch.io 逐包许可证记录，04_Platform/00_Compliance.md 第 4 节）、素材来源致谢页截图。

### E. 发布材料
微信小游戏构建产物、版本号、构建时间、依赖说明、发布说明、配置说明、版本回退方案、已知问题说明。

## 2. 最终验收清单

- [ ] 游戏正常启动；新玩家完成教学流程
- [ ] 卡牌选择、战斗结算、资源增减、道具使用、状态效果、连击、出口条件均正确
- [ ] 通关奖励不重复发放；失败重试流程正确
- [ ] 存档可读；旧版存档有迁移/回退策略
- [ ] 500 关配置通过验证；关键关卡有通关验证记录
- [ ] UI 风格统一；多尺寸布局正常
- [ ] 无已知严重阻断问题
- [ ] 工程可由其他开发者按文档重建
- [ ] 测试报告与交付清单齐全

## 3. 风险与控制（2026-10 增补）

| 风险 | 问题 | 控制 |
|---|---|---|
| 过早制作 500 关 | 核心规则未稳，大量返工 | 先 10～20 关验证理解度/平衡/策略差异，再扩展 |
| AI 代码过度耦合 | 逻辑全写进单文件 | 模块边界 + 任务模板（09_Workflow.md）+ 限定文件 + 强制测试 + 审查 |
| 卡牌规则不统一 | 各改各的，规则冲突 | 统一 EffectResolver/结算顺序/错误处理，全效果有测试（03_ActionQueue.md） |
| 关卡数量达标质量不足 | 高度重复或不可解 | 主题机制组合表、记录核心策略点、自动验证、关键关人工通关、数据调优 |
| 视觉表现不统一 | 多人/AI 生成风格漂移 | 设计令牌 + 组件库 + 标准卡牌模板 + 命名规则 + 视觉验收（03_UI/00_UiSpec.md 第 8 节二次加工规范） |
| 第三方素材授权风险 | itch.io 免费包许可证差异大，误用 NonCommercial 包有下架/版权风险 | 逐包许可证审计（00_Compliance.md 第 4 节）+ 授权清单归档 + 构建 license 核对脚本 |
| 钱包经济通胀 | 商店消耗口不足，金币贬值、商店形同虚设 | 16_Shop.md §5 监控预案（存量增速/购买率阈值 → 价格系数调整）；DIFF 权重校准闭环 |
| 暗堆随机挫败 | dark 堆翻出强敌/陷阱的负反馈劝退 | R 因子定价 + 浅堆配比 ≥40% + 张数角标信息；实测劝退则降暗堆陷阱权重（Balance 层，不动规则） |
| matrix5 多堆渲染性能 | 20 堆 × 动效逼近 DrawCall/帧率预算 | 对象池（05_Performance.md）+ 140 缩略卡渲染 + perf_checkpoint 埋点监控 |
| 双层经济理解成本 | 新玩家混淆局内金币与钱包金币 | 主界面不显示局内金币 + 货币说明气泡 + 首次转存提示（15_Tutorial.md §6 hint_wallet_deposit） |

### 3.1 V1 边界决策（2026-10，明确不做 / 延后）

| 项 | 决策 |
|---|---|
| 云存档 | **V1 不做**（本地备份链 + HMAC 已防损坏；换机/清缓存数据丢失为已知风险，接受）。开放数据域只写榜数据、不回灌存档；云存档待有需求再立项 |
| 低端机性能降级 | 技术验证阶段（里程碑 B）冻结预算时一并设计降档开关（画质/粒子/帧率） |
| 强制更新与最低可玩版本 | 上线前（里程碑 F）随 07_Ops_Release.md 版本通道细化 |
| 无障碍细则 | 美术打磨期细化（现状：色弱不依赖单色 + 44px 热区 + 数字角标冗余已达标底线） |
| 转场表现规范 | 美术打磨期细化（时长上限已受 00_UiSpec.md §5.1 约束） |
| 多语言翻译流程 | 架构已预留（SettingsData 语言字段 + CopyDeck key + LocalizationValidator），V1 单语中文 |
